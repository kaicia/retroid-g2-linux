# G2 boot test — Path A Stage 0, then (optionally) Path C — 2026-09-29

Goal: the project's first on-device kernel output, using the SM8635 kernel that
now builds end-to-end (`docs/g2-holodor-make-kernel-20260929.md`).

## Where the boot routes stand
| Route | Status |
|---|---|
| Path A — SD, EFI removable fallback, ESP-typed card | Closed 2026-09-15 (`g2-path-a-closed-20260915.md`) |
| `fastboot boot` (RAM boot) | Closed 2026-09-15: `unknown command` (`g2-fastboot-boot-unsupported-20260915.md`). *`g2-path-a-reverify-20260929.md` wrongly called this unconfirmed; corrected there.* |
| **Path A Stage 0** — SD in the RP5's exact production arm-efi shape | **Untested → Test 1.** No internal write. |
| **Path C** — our v2 boot image EDL-written into the *active* `boot_b` | **Untested → Test 2.** Writes internal storage; the user's call. |
| Path B — replace ABL | Needs a Cliffs ABL (ROCKNIX LinuxLoader is private) |

## Fixes made before any boot attempt
All would otherwise have wasted a test:
1. **Storage-path drivers were modules.** holodor boots with no initramfs, so
   `gcc`/`pinctrl`/`icc` as `=m` could never load before root. Now `=y`
   (regulator, SDHCI, SMMU, rpmh, cmd-db already were).
2. **No screen driver.** `/chosen` carries a `simple-framebuffer` at 0xe3940000,
   but `CONFIG_FB_SIMPLE` was off (DRM is a module). Now `=y`, with
   `FRAMEBUFFER_CONSOLE=y` — the display is the console.
3. **cmd-db missing.** rpmh-rsc (and so the bcm-voter, PMXR2230 regulators and
   every interconnect vote) defers until `cmd_db_ready()`. The
   `aop_cmd_db_region` now carries `compatible = "qcom,cmd-db"`, as the vendor
   tree's does (verified in the dump).
4. **No earlycon.** Dropped from the cmdline and profile: an unclocked GENI write
   can hang (`g2-tier0-fastboot-plan-20260915.md`); the UART is not exposed anyway.
5. **Boot image layout.** `mkbootimg-g2.py` left 16 MiB between kernel and
   ramdisk; a real SM8635 Image is far larger. Ramdisk/dtb moved up (kernel gets
   128 MiB) and the packer now refuses an overlapping Image.

## Test 1 — Path A Stage 0 (no internal write)
Artifact: `release/tier0-stage0/g2-stage0-sd.img.xz`
(built by `scripts/build-g2-stage0-sd-image.sh`; menu `boot/grub-stage0.cfg`).

Card layout = holodor/RP5 arm-efi contract: p1 FAT32, GPT name `system`,
`legacy_boot` attribute, **basic-data type (not ESP)**, label `ROCKNIX`, fixed
PARTUUID; `/EFI/BOOT/bootaa64.efi` (GRUB), `/boot/grub/{grub.cfg,cliffs-g2.dtb}`,
`/KERNEL`. p2 ext4 `POCKNIX_ROOT` (empty).

Steps:
1. Write the image to a spare microSD (balenaEtcher / Rufus in DD mode; the
   `.xz` can be given directly to Etcher). **Everything on that card is lost.**
2. Power the G2 off, insert the card, power on normally.
3. Read the result:

| On screen | Meaning | Next |
|---|---|---|
| A GRUB menu ("G2 Stage 0: GRUB reached …"), waiting | **Path A works.** Factory ABL chainloads SD EFI in this shape. | Pick the first entry → see below |
| Android boots as usual | Path A closed against the RP5 contract too | Remove card. Decide on Test 2 |
| Anything else (hang on logo, bootloader screen) | Unexpected — photograph it | Remove card, hold power to restart |

If GRUB appeared and you picked the kernel entry:
| On screen | Meaning |
|---|---|
| Scrolling kernel log, ending in `VFS: Unable to mount root fs` (or stopping) | **First kernel output. Tier 0 done.** There is no root fs yet; this is the success signal. Photograph the last screen. |
| GRUB error text | Photograph it (GRUB could not load KERNEL/dtb) |
| Black screen | Kernel may have started with no console (EFI GOP vs simple-framebuffer) — photograph, report |

To get back to Android: hold power until it turns off, remove the card, power on.

## Test 2 — Path C: write our boot image into `boot_b` (writes internal storage)
**Only if Test 1 shows Android, and only if you decide to.** This replaces the
active slot's kernel partition, so Android will not boot until you restore it.
Restore is an EDL write of your own backup — the same tool and loader that
recovered the device on 2026-09-20.

Artifact: `release/tier0-pathc/g2-pathc-boot.img` — Android boot image
header v2 (kernel + our DTB inside, empty initramfs), cmdline
`console=tty0 loglevel=8 ignore_loglevel`.

Why it should reach the kernel: ABL boots `boot_b` every day; this is that exact
path, just with our kernel. Known unknowns: (a) whether this ABL accepts a
header-v2 image on a GKI device (stock is v4 + `vendor_boot`); (b) whether
ABL's `dtbo_b` overlay step tolerates a DTB that lacks the vendor labels. Either
failing shows up as "stays on the logo / drops to the bootloader", and is fixed
by the restore below.

Why the slot will not be lost: `slot-successful:b:yes`, so ABL does not
decrement b's retry count on failed boots and will not mark it unbootable.

Prerequisites (same as the recovery): device in EDL 9008, WinUSB via Zadig, in
the `edl-master` folder with `xbl_s_devprg_ns.melf` and the two `firehose.py`
patches; the factory backup folder present, containing `boot_b` (96 MiB).

```
python edl.py w boot_b g2-pathc-boot.img --loader=xbl_s_devprg_ns.melf --memory=UFS
python edl.py reset --loader=xbl_s_devprg_ns.melf
```
(`Pipe error` on reset is normal.) Then watch the screen as in Test 1's kernel
table. An orange "device is unlocked" warning first is expected.

**Restore Android** (enter EDL again: power off, hold the EDL key combo / use the
same method as the recovery):
```
python edl.py w boot_b <factory-backup>\lunN\boot_b.bin --loader=xbl_s_devprg_ns.melf --memory=UFS
python edl.py reset --loader=xbl_s_devprg_ns.melf
```
(`lunN` = whichever LUN folder of the backup holds `boot_b`; search the backup
for `boot_b`.) If Android then still does not come up, run the proven slot
sequence from `g2-EDL-recovery-runbook.md`:
```
python edl.py setactiveslot b --loader=xbl_s_devprg_ns.melf
python edl.py setbootablestoragedrive 2 --loader=xbl_s_devprg_ns.melf
python edl.py reset --loader=xbl_s_devprg_ns.melf
```
**Never** run `fastboot set_active` — switching slots is what bricked the device.
